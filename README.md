# SE Workflow｜同学交接

本版串联课堂作业 1、2、3。讨论记录先提炼为带原文证据的要点，再按提案轮次登记每位参与者的立场。修订时回应上一轮的异议，由参与者重新确认。同一轮全员同意后，共识才转入产品想法。之后生成需求规格和设计规格，分解开发任务，制定测试方案，把用例绑定到测试任务，再统一编排编码、测试与代码评审。编排结果回填到设计规格。运行记录展示各阶段的开始、完成及失败，执行页提供人工补充、异常处理和交付确认。

## 先打开看一遍

1. 完整解压。电脑需要 Node.js 22 或更新版本。
2. Windows 上双击 `Start.cmd`，或在项目目录运行 `npm start` 后访问 [工作台](http://127.0.0.1:8765/)。
3. 点击页面右上角的「DeepSeek 密钥」，输入自己的 API 密钥。可进入「讨论与共识」填入讨论，也可在「规格与编排」直接选择案例。点击「运行完整流程」后，产物会逐阶段出现。顶部「运行记录」可随时查看进度。密钥仅在当前页面使用，刷新后需重新输入。

包里已带可运行的前端文件，首次启动无需安装依赖。在线生成需要能访问 DeepSeek API 和可用的 API 密钥。若有之前从工作台导出的 DeepSeek JSON，可以通过「导入 DeepSeek 结果 JSON」离线回放。

## 分工时从哪里改

| 要改的内容 | 修改位置 |
| --- | --- |
| 页面布局、样式、按钮及导出 | `index.html`、`style.css`、`app.mjs` |
| 演示想法与 Design Spec | `examples.mjs` |
| PM Agent 提示词、DeepSeek 请求、错误处理 | `server.mjs` |
| 任务校验、交付物依赖、测试前置、执行批次与编排自校验 | `workflow.mjs` |
| 需求、设计、任务和测试方案的编号关联 | `pipeline.mjs` |
| 讨论证据校验、任务状态与前置完成检查、回退范围 | `interaction.mjs` |
| 提案轮次、逐人立场与共识确认条件 | `consensus.mjs` |
| 讨论蒸馏结论、G2 门控判定与决策表导出 | `distill.mjs` |
| 执行 Agent 职责、节点产物验证与交接 | `agents.mjs` |
| 可观测记录、讨论确认与执行交互界面 | `observability.mjs` |
| 前端构建和 Windows 程序打包 | `build.mjs` |

`app.browser.js` 是构建生成的浏览器脚本。改动 `app.mjs`、`examples.mjs` 或 `workflow.mjs` 后，先在项目目录运行一次 `npm ci`，再运行 `npm run build` 并刷新页面。改了 `server.mjs` 或编排逻辑后，重启服务再验证。

## 构建可双击运行的程序

在 Windows x64 上使用 Node.js 26 或更新版本。运行 `npm ci` 和 `npm run build:windows` 后，生成文件是 `dist/SE-Workflow-Classroom.exe`。

## 改完后验证

先跑「旅游行程分配」，点每日时长限制对应的需求，检查关联的开发和测试任务。再换「校园活动报名」，点击一条依赖并查看前置交付物，将并行上限改为 1，确认每批只排一项。最后导出 JSON，再导入一次检查能否回放。详细上台顺序见《课堂展示与使用说明》。

编排器先排下游链最长的任务，让关键路径尽早开工，并在并行上限内把每批排满；前置任务、交付物和依赖图由同一份输入生成，编排结束后会自校验批次与依赖是否一致。测试或评审失败后，回退只重置目标实现及其全部下游，无关分支与历史记录保留，每轮回退都有可区分的轮次标识。`npm test` 覆盖批次划分、编排自校验、回退范围、重跑门禁与回退因果。

编排器检查任务结构与先后关系。验收标准是否符合业务需要，仍要对照原始规格核对。压缩包未附带 API 密钥。

## 第三次作业的展示

同一契约下可独立开发的模块可以并行。每项编码交付后，其单元测试与代码评审可以并行。消费该编码交付物的任务等待对应单元测试。共享接口的组件或有实际交接的实现进入联调，端到端验收等待联调及代码评审。测试任务内可打开对应的 TC 用例，查看测试步骤和预期结果，导出的 `task.md` 也保留用例内容。

测试或评审失败后，负责人根据证据选定有缺陷的实现。执行页预览回退范围，将目标实现标记为待修复，让依赖它的任务按前置关系重新执行，并保留历史记录。代码修复和交付由任务负责人执行。

打开《第三次作业展示说明.md》，按讨论主线、连续产物、执行交互三部分展示。在「执行与交互」可逐个调用节点 Agent，或并行调用前置已就绪的节点。不同角色通过 DeepSeek API 生成契约、代码、测试脚本和评审报告。确认交付的文件正文会随依赖传给下游。测试脚本下载后需要在项目环境运行，并填写实际结果。通过「导出 JSON」可回放产物和过程，通过「导出 task.md」可查看工种、Agent、执行状态与交付文件名。
